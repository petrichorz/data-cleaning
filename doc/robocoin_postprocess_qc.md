更新日期：2026-11-14。

**范围：55D 转换完成后的独立阶段，当前暂不实现或执行。**

action/state 相等检查、运动判定、下一帧目标构造及其末帧处理均移到这里讨论。
下文保留此前的样例证据和候选条件；这些条件不限制 55D 格式转换，

## action/state 相等与时间语义：既有检查与候选方案

### 4.1 本地样例检查结论

本地检查发现，以下四组样例的所有 episode 都满足：

```python
eef_sim_pose_action[t, 0:6] == eef_sim_pose_state[t, 0:6]   # 左侧位置和欧拉角
eef_sim_pose_action[t, 6:12] == eef_sim_pose_state[t, 6:12] # 右侧位置和欧拉角
```

| 数据集 | episode 数 | 帧数 |
|---|---:|---:|
| `AIRBOT_MMK2_mobile_car` | 49 | 6,327 |
| `Airbot_MMK2_storage_block_both_hands` | 48 | 3,676 |
| `Galaxea_R1_Lite_move_mouse` | 29 | 7,982 |
| `RMC-AIDA-L_box_up_down` | 157 | 26,097 |
| 合计 | 283 | 44,082 |

此处是每一侧的 action 与自身同帧 state 相等，不是左右侧彼此相等。
比较覆盖上述样例的每帧、全部 12 个分量，最大绝对差值为 0；
EEF 的相等本身不能推出其他字段也相等。随后对上述四组本地样例的原始列逐行、逐分量复核，结果如下：

| 数据集 | `observation.state` / `action` | `eef_sim_pose_state` / `eef_sim_pose_action` | `gripper_open_scale_state` / `gripper_open_scale_action` |
|---|---|---|---|
| `AIRBOT_MMK2_mobile_car` | 全部 36 维同帧相等 | 全部 12 维同帧相等 | 无此字段 |
| `Airbot_MMK2_storage_block_both_hands` | 全部 36 维同帧相等 | 全部 12 维同帧相等 | 无此字段 |
| `Galaxea_R1_Lite_move_mouse` | 全部 14 维同帧相等 | 全部 12 维同帧相等 | 全部 2 维同帧相等 |
| `RMC-AIDA-L_box_up_down` | 全部 28 维同帧相等 | 全部 12 维同帧相等 | 全部 2 维同帧相等 |

以上比较覆盖本地全部 283 集、44,082 帧；对应列维度和字段名顺序一致，数值均有限，
差异行数为 0、最大绝对差值为 0。此结论仅覆盖本地现有数据，尚未验证其他机器上的全量数据。
同帧 state/action 相等不表示轨迹在时间上静止，也不能仅凭相等断定数据生成过程一定复制了 state。

### 4.2 后处理候选流程：判定与目标构造（待确认）

以下保留此前参考同事脚本讨论的方案，供后处理质检阶段评估；不是当前已启用的转换流程：

```text
读取一个完整的原始 episode
    ↓
分别映射 state/action 到 55D，生成 mask_state/mask_action
    ↓
结合原始字段、55D 和 mask 判定整集是否“动态且同帧精确相等”
    ├─ 满足全部条件：整条 55D action 改用下一帧 55D state
    └─ 不满足条件：保留初步映射的发布 action，记录未转换原因
    ↓
保存最终 55D、mask、动作来源、判定依据，并保留原始列
```

执行顺序是先映射到 55D，再进行这一项动作语义判定；判定仍然需要回查原始数据，
不能只比较转换后填零、归一化或精度转换后的数组。这也不意味着所有质检都必须放在映射之后。

### 4.3 整集判定条件与比较范围

此前候选方案提出以下保护条件，是否采用及具体边界留待后处理阶段确认：

1. episode 至少有 3 帧；比较覆盖整集，不使用抽样或只比较首尾帧。
2. state/action 已映射的语义槽位集合一致；对应分量定义、单位、参考系和旋转约定一致。
   关节按名称对应；EEF 按映射文档第 1 节固定布局对应，不要求 `rot_*` / `ori_*` 分量名称字符串相同。
3. 按映射配置取回源列及分量，要求值有限，并逐帧、逐分量精确相等。
   使用精确比较，不用 `allclose` 容差将近似相等认定为完全相等；55D 空槽位的填零不构成证据。
4. 额外按名称匹配原始 `observation.state` / `action` 的共有分量并精确比较。
   即使某些手指关节超出 55D 容量而未被映射，也应参与这层共有分量检查。
   未命名分量不参与比较，其存在本身不阻止下一帧替换；判定结论仅表示检查范围内整集相等，
   不能宣称未检查的原始分量也相等。
5. 整个 `mask_state` 与 `mask_action` 一致。用于运动判断的核心槽位为
   双臂关节 `0:14` 和夹爪 `28:30`；至少有一个有效核心分量，且参与判断的核心分量全程有效。
6. 在上述有效核心分量中，至少有一次相邻帧变化的绝对值超过 `1e-6`。
   没有变化时记录 `static_ambiguous`，不因静止时 state/action 相等就构造下一帧目标。

运动判断暂沿用同事的核心槽位范围，不把 EEF 或手指加入该范围。
双臂关节按映射文档第 7 节映射；仅有 EEF 变化、没有有效核心分量变化时，不触发转换。

比较字段必须跟随我们选定的来源补全，不能照搬同事旧配置的字段覆盖范围：

- EEF：比较 `eef_sim_pose_state/action` 中左右位置和左右欧拉角，覆盖完整 12 维。
  不能只检查 xyz；相等判定使用源欧拉角，避免转换后的四元数符号影响这项精确比较。
- 夹爪：存在有效映射时，显式比较独立的 `gripper_open_scale_state/action` 左右两维。
  原始 state/action 内部夹爪分量的比较不能替代这一步。
- 灵巧手没有独立夹爪字段时，夹爪占位及其零 mask 不提供有效开合量证据，
  仍需检查其他已映射字段和原始共有分量。
- 分别保存左/右 EEF 位置、姿态、左/右夹爪的检查结果。存在缺失、语义不一致、无效值或任意差异时，
  不能把该 episode 判为满足整集转换条件。

### 4.4 满足条件后的动作与 mask

对满足第 4.3 节全部条件的 episode，采用下一帧状态目标，记为 `derived_next_state`：

```python
action_unified = np.zeros_like(state_unified)
mask_action = np.zeros_like(mask_state)
action_unified[:-1] = state_unified[1:]
mask_action[:-1] = mask_state[1:]
```

- 替换整个 55D 动作向量，所有有效语义使用同一下一帧目标，不只移动 EEF。
- 最后一帧没有下一状态，因此整条 action 和 mask_action 都置 0。
- 严格限制在同一 episode 内，不跨集取目标。
- 目标时间跨度是下一条状态记录，即 `source_step=1`，不据此推断真实控制延迟。
  发布时间网格不能冒充实测动作时长；物理时间与采样间隔的落盘字段另行确定。

这是一项候选训练目标构造策略，不是对原始控制命令的恢复，
也不证明发布 action 一定是复制生成的。原始列必须保留，不能被重构后的 55D action 覆盖。

### 4.5 不满足条件与混合情况

不满足整集条件时保留初步映射的发布 action，记为 `source_native`，记录具体原因。
此标签只表示保留来源，不证明它是真实控制命令，也不等于质检合格；
无效值及训练有效性仍按独立质检和 mask 规则处理。

| 检查情况 | 处理 |
|---|---|
| 所有参与比较的字段整集精确相等，且语义、mask、运动条件均满足 | 整条 55D action 改为下一帧 55D state |
| EEF 相等，但任一侧独立夹爪字段不同 | 保留发布 action，记录夹爪差异；不单独移动 EEF |
| EEF 位置相等，但任一侧欧拉角不同 | 保留发布 action，记录姿态差异 |
| 已映射字段相等，但原始共有分量不同 | 保留发布 action，记录原始分量差异 |
| 仅部分帧或片段相等 | 不触发整集转换，不逐帧切换两种动作来源 |
| 静止、过短、无效值、mask 或语义不满足条件 | 不触发转换，记录原因供复核 |

转换结果至少记录 episode 级的模式、原因、比较范围及各语义检查结果；
逐行记录动作来源与目标步数。派生分支非末帧目标步数为 1，末帧为 0 且动作 mask 全 0；
保留源动作分支的目标步数不能被解释为已验证的控制时间跨度。

以上仅保留讨论记录；后处理是否构造下一帧目标仍待确认，不自动启用，也不自动删除 episode。
