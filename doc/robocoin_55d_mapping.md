# OpenWAM RoboCOIN → 55D 语义映射规则

更新日期：2026-11-14。

本文记录逐项讨论的转换规则，供后续实现和质检使用。当前确定范围为双臂关节、EEF、夹爪、灵巧手、
腰/头/底盘不接入的规则；先完成 55D 映射，再按完整 episode 执行同事的动作策略。
对应实现为 [processor/convert_robocoin_55d.py](../processor/convert_robocoin_55d.py)，
运行方式及原地追加说明见 [README](../README.md#robocoin-转-55d)。

本地调试数据位于 `/mnt/sfs_turbo/public/datasets/openwam-robocoin/RoboCOIN/`。
此处只有部分样例，样例检查结果不能直接推广到其他机器上的全量数据。

转换仅新增 `state_unified`、`action_unified`、`mask_state`、`mask_action` 四列，并另写转换记录，
保留原始列、数值和原始字段定义，不覆盖原始 `action`。
直接在原来的 `data/*.parquet` 增加四列：先写同目录临时文件，完整写完后替换原文件，
保留原始列内容，最终路径和文件数量不变。全部文件成功后，在原 `meta/info.json` 中登记
四个长度 55 的 float32 字段；其他元数据和视频保持原样。转换记录保存在原子数据集的 `qc/` 中。
中断后可重跑，从原始列重新生成四个派生字段，不重复追加；本轮错误和汇总报告重新生成。
原始向量中有数值但无名称的分量继续原样保留，不补名、不推断语义、不用于 55D 映射。
不因整个向量的名称数量与实际宽度不一致就拒绝转换；按名称取数时校验实际使用的名称和索引有效。

位置、臂关节、手指关节和夹爪沿用数据集原始定义，直接保留源数值。
本阶段不指定新的物理单位、不校验或猜测单位，也不做单位换算或坐标系变换。
已确定的欧拉角转四元数按 OpenWAM 的读取约定执行，具体见第 2.2 节。

## 1. 55D 映射总表

每一帧先分别读取各自原始来源，生成 55D state/action；整集符合第 4 节条件后，再替换派生 action。
EEF 就是机械臂末端：位置表示“在哪里”，姿态表示“朝哪个方向”。

下面按数组下标从 0 开始写；例如 `0:7` 表示下标 0～6，共 7 维。
`*` 对 state 取 `_state` 列，对 action 取 `_action` 列。
臂关节和手指则分别从 `observation.state`、`action` 中按名称取值。

| 55D 下标 | 维数 | 表示什么 | 从哪里取 | 怎么处理 |
|---|---:|---|---|---|
| `0:7` | 7 | 左臂关节角 | `left_arm_joint_N_rad` | 按关节编号排序，原值保留；6 个关节时末尾补 0、mask=0，7 个全部填入 |
| `7:14` | 7 | 右臂关节角 | `right_arm_joint_N_rad` | 与左臂相同；按名称找右臂，不依赖它在原始数组中的位置 |
| `14:17` | 3 | 左末端位置 | `eef_sim_pose_*[0:3]` | 直接保留 x、y、z 原值 |
| `17:21` | 4 | 左末端朝向 | `eef_sim_pose_*[3:6]` | 将 3 个欧拉角转成 4 个四元数分量，顺序为 `[qx,qy,qz,qw]` |
| `21:24` | 3 | 右末端位置 | `eef_sim_pose_*[6:9]` | 直接保留 x、y、z 原值 |
| `24:28` | 4 | 右末端朝向 | `eef_sim_pose_*[9:12]` | 与左末端相同：欧拉角转四元数 |
| `28:29` | 1 | 左夹爪开合 | `gripper_open_scale_*[0]` | 原值保留，0 为闭合、1 为张开，中间值也保留；没有该字段则值和 mask 都为 0 |
| `29:30` | 1 | 右夹爪开合 | `gripper_open_scale_*[1]` | 与左夹爪相同 |
| `30:36` | 6 | 左手手指关节角 | 左手的 `left_hand_joint_*` 关节字段 | 按名称匹配、按编号排序；1～6 个按顺序填入，尾部补零；超过 6 个整只左手不放入，值和 mask 都为 0 |
| `36:42` | 6 | 右手手指关节角 | 右手的 `right_hand_joint_*` 关节字段 | 与左手相同，左右分别判断；没有手指字段时值和 mask 都为 0 |
| `42:46` | 4 | 腰/躯干 | 不读取到 55D | 全部填 0，mask=0 |
| `46:48` | 2 | 头/颈 | 不读取到 55D | 全部填 0，mask=0 |
| `48:51` | 3 | 底盘 | 不读取到 55D | 全部填 0，mask=0 |
| `51:55` | 4 | 预留位置 | 没有来源 | 全部填 0，mask=0 |

合计 **55 维**：双臂 14 + 双末端 14 + 夹爪 2 + 双手 12 + 腰 4 + 头 2 + 底盘 3 + 预留 4。

读这张表时记住以下几条：

- **只新增字段，保留原始内容。** state、action、两个 mask 都新增为长度 55 的字段，原始列和行数保持不变。
- **成功映射的维度 mask=1，未映射或补出来的维度 mask=0。** 真实值刚好是 0 时，mask 仍为 1；结构错误导致整行作废时，两个 mask 全部为 0。
- **沿用数据集原始定义。** 位置、关节和夹爪保留原值，不换单位、不做训练归一化；姿态沿用 OpenWAM 的读取约定转为四元数，暂不额外处理正负号或时间连续性。
- **双臂每侧必须有连续编号的 6 或 7 个关节。** 缺侧、缺号或数量不符按第 7 节报错；手指超过容量只屏蔽该侧手部。
- **NaN/Inf 只屏蔽受影响的维度，不删行。** 关节、位置和夹爪逐维置零并设置 mask=0；任一欧拉角无效或姿态转换失败时，该侧四元数四维一起屏蔽。state/action 独立处理，未映射分量的异常只记录；见第 2.3 节。

统一补零规则：通过对应语义的字段定义校验后，state/action 及各自 mask 均以 55 维全零初始化，
只将可映射的有效分量写入并将对应 mask 置 1；最终缺失、未接入及预留分量保持值为 0、mask=0。
真实有效值恰好为 0 时 mask 仍为 1，不能按值是否为零生成 mask。
补零仅作用于新增的 55D 字段，不修改原始列；第 7 节已确定的臂关节结构校验仍保留。
数值异常按第 2.3 节局部屏蔽；向量缺失、维数错误等结构问题仍按整行置零处理。

- `state_unified` 的臂关节和手指来自 `observation.state`，EEF 和夹爪来自对应的 `_state` 列。
- `action_unified` 读取并转换同一原始行对应的 action 来源；时间对应关系见第 4 节。
- EEF 沿用 OpenWAM 的固定切片读取：`0:3` 为左位置，`3:6` 为左欧拉角，
  `6:9` 为右位置，`9:12` 为右欧拉角。输入按每帧 12 维布局处理，
  不根据分量名称重排，不建立 `eef_rot_*` / `eef_ori_*` 别名匹配表。
- 双臂和灵巧手仍按各自关节名称匹配、按编号排序，具体见第 5、7 节。
- 不混用机器人 SDK 原始 EEF 字段与 `eef_sim_pose_*`。发生源列缺失或布局不符时，不静默切换来源。

## 2. EEF 转换规则

### 2.1 位置直接保留原值

按固定切片取出左右末端的 x、y、z，直接填入 55D。
单位、坐标轴方向、原点和末端参考点均沿用数据集原始定义，转换阶段不重新规定或校验。
不做缩放、坐标变换或位置差分；原始元数据保持不变。

### 2.2 欧拉角转换为四元数

采用与 OpenWAM RoboCOIN 读取路径一致的解释：

- 沿用 OpenWAM 对源欧拉角的解释：按弧度读取 `[roll_x, pitch_y, yaw_z]`，不额外换算输入值。
- 旋转约定为外禀 XYZ，对应 `R = Rz @ Ry @ Rx`。
- 输出为单位四元数，顺序固定为 `[qx,qy,qz,qw]`。

等价的转换表达为：

```python
from scipy.spatial.transform import Rotation

quat_xyzw = Rotation.from_euler("xyz", euler_xyz, degrees=False).as_quat()
```

这里小写 `xyz` 表示外禀旋转。OpenWAM 将同一旋转转换成旋转 6D，
55D 模板使用四元数；二者表示形式不同，采用的旋转含义保持一致。

本阶段直接保存逐帧欧拉角转换得到的四元数，不额外统一正负号，不做相邻帧符号连续化。
四元数符号和跨越 180° 的数值连续性不在当前 55D 转换中处理。

这是基于现有读取代码和此前样例核验选定的解释，并非对任意原始机器人 SDK 欧拉角的通用假设。
此前 AgiBot 的数值对齐包含参考系差异分析，不能据此宣称所有机器人都已独立验证。

转换应检查输入是否有限、输出四元数是否为单位长度。无效姿态不能通过填入一个看似有效的旋转来掩盖。

### 2.3 错误处理：数值异常局部屏蔽，结构错误整行置零

“一行”是一帧，不是一个 episode。数值异常沿用同事的逐维屏蔽方式：

| 情况 | 新增 55D 字段的处理 |
|---|---|
| 某关节、手指、位置或夹爪分量为 NaN/Inf，或元素为 null | 只把对应维度数值和 mask 置 0 |
| 有限原值转为 float32 后溢出 | 只屏蔽该输出维度，并记录溢出错误 |
| 某侧任一欧拉角为 NaN/Inf，或转换无法生成有效四元数 | 该侧四元数四维一起置 0、mask=0，位置和另一侧照常处理 |
| 未映射分量存在 NaN/Inf，例如超出容量的手指或未命名尾部 | 记录来源错误，不影响任何有效的 55D 槽位 |

state 与 action 独立处理：state 某维度无效，不会连带屏蔽 action。
原始 `observation.state`、`action`、`eef_sim_pose_state/action` 和存在的
`gripper_open_scale_state/action` 仍检查全部分量；记录异常不等于整行作废。
三个欧拉角均为 0 是有效姿态；有限但可疑的数值保留给后续质检，不猜测单位或自动裁剪。

结构问题仍沿用原有规则：必需的整个来源向量为空、不是一维、EEF/夹爪长度不符、
已映射关节索引越界、包含不能解释为数值的元素时，无法按既定布局读取，
该行 `state_unified`、`action_unified`、`mask_state`、`mask_action` 全部置零，记录错误并继续。
正常不存在的夹爪字段、未接入槽位和预留槽位按补零规则处理，不因此报错。

以上处理只修改新增列，原始列、episode、帧号、时间戳和视频对应关系均保留。
不会因为某一帧的异常自动屏蔽整个 episode 或整个 Parquet。

错误写入子数据集 `qc/conversion_errors.jsonl`，包含源文件、行号、episode/frame、
来源字段和分量索引、错误类型和说明。`result` 表示该行处理结果：

- `components_masked`：仅部分维度因异常被屏蔽。
- `source_only`：异常只在未映射分量中，55D 无需改变。
- `row_zeroed`：结构错误导致四个新增向量整行置零。

`masked_state_indices` / `masked_action_indices` 记录该行因数值异常屏蔽的输出下标，
不包括正常补零的槽位；`row_zeroed` 表示整行作废，不靠这两个列表表达其范围。
NaN/Inf 在日志中用字符串表示；同一帧可以记录多条错误，但行计数只算一次。
摘要中 `error_rows` 为有错误记录的行数，`masked_rows` 为局部屏蔽行数，
`zeroed_rows` 为结构错误导致的整行置零数；只记录未映射异常的行不计入后两项。
摘要的错误行计数覆盖本轮已检查的行，包含最终写入失败文件中的检查记录；
`rows` 和 `zeroed_rows` 则只统计成功写入的文件。
每次运行重新生成日志和摘要，文件/子数据集级错误另注明范围，不伪造帧号。

## 3. 夹爪转换规则

`gripper_open_scale_*` 使用连续归一化开合量：**0 表示完全闭合，1 表示完全张开**。

- 保留发布值，不翻转开闭方向，不二值化。
- 不按 episode 做 min-max 归一化，不在落盘转换时应用训练读取器的 `[-1,1]` 归一化。
- state/action 使用相同的开合方向与量纲定义，但不要求二者数值相等。
- 不同机器人同为 `0.5`，不代表具有相同的物理开口宽度。
- 本地已检查样例的该字段落在 `[0,1]`；NaN/Inf 按第 2.3 节仅屏蔽对应夹爪维度并记录错误。
  有限但越界的值保留，不静默截断，留给后续质检。

灵巧手数据如果没有 `gripper_open_scale_*`，对应夹爪槽位填 `0`、对应 mask 置 `0`。
这个 0 是缺失占位，不表示夹爪闭合。不得从手指关节角凭空推算一个标为有效的夹爪开合量；
灵巧手关节按第 5 节独立映射。

## 4. 整集动作判定与时间对应关系

先按原始行转换到 55D，再沿用同事的整集规则。全部满足以下条件才构造下一帧目标：

1. episode 至少 3 帧；按 `episode_index` 分组、`frame_index` 排序。允许跨 Parquet，
   不在文件或 4096 行 I/O 批次边界截断。ID 无效、帧号缺失/重复/不连续时保留初步转换结果并记录原因。
2. state/action 的映射槽位和对应语义一致。关节按名称对应；EEF 使用本文确定的固定布局。
3. 每个映射字段的原始值全程有限、逐帧严格相等，包括完整 12 维 EEF 和存在的独立夹爪字段。
4. 原始 `observation.state` / `action` 的所有同名分量也全程有限且严格相等，
   包括超过 6 维未放入 55D 的手指；不自行补名，不比较没有名字的尾部。
5. 两份 55D mask 完全一致。核心槽位为双臂 `0:14` 和夹爪 `28:30`，至少有一个有效核心分量，
   且参与判断的核心分量全程有效。正常不存在的槽位不阻止判断。
6. 核心分量至少有一次相邻帧变化超过 `1e-6`。仅 EEF 或手指变化不能满足这项条件。

全部满足时，模式为 `derived_next_state`：

```python
action_unified[t] = state_unified[t + 1]
mask_action[t] = mask_state[t + 1]
# 同一 episode 最后一帧：action_unified 和 mask_action 全部置零。
```

任一条件不满足就采用 `source_native`，保留初步转换的 action/mask（包括末帧），
不只移动相等的某个夹爪或 EEF。此规则构造训练目标，不证明发布 action 的真实生成过程或控制延迟。

仅修改新增的派生 action/mask。原始列、state_unified、mask_state、文件行数及行顺序不变。
重跑从原始列重新计算，不对已移位的 action 再移一次。
`qc/episode_policy.jsonl` 逐集记录模式、原因和来源文件；`qc/conversion_summary.json`
汇总判断数量、移位/保留数量和原因。是否全部写回仍以转换完成状态为准。
详细说明与样例证据见 [动作策略记录](robocoin_postprocess_qc.md)。

## 5. 灵巧手转换规则

### 5.1 按每侧完整通道数决定是否映射

以元数据中每侧手的**完整关节通道数**判断容量，不用手指数或推测的独立自由度数判断。
记录了 12 个关节数值就按 12 个通道处理；没有明确的耦合定义时，不自行压缩成 6 个自由度。
这是一项通用规则，不表示已经在本地数据中证实某只手存在这样的耦合关系。

| 每侧手的情况 | 该侧 55D 手部槽位处理 |
|---|---|
| 有 1～6 个语义明确、state/action 能对应的关节通道 | 按固定顺序写入，实际可用维度 mask=1；尾部填 0、mask=0 |
| 超过 6 个关节通道 | 该侧全部填 0、mask=0，不截取前 6 个、不降维 |
| 没有手部关节字段 | 该侧全部填 0、mask=0 |
| 关节定义有歧义，或 state/action 名称不能完整对应 | 该侧暂不映射，填 0、mask=0，记录原因并标记待复核 |
| 某个已确定关节的数值元素为空 | 只屏蔽该维度并记录错误；整个向量缺失或索引越界仍按结构错误处理 |
| 任一手指关节出现 NaN/Inf，包括未进入 55D 的手指 | 已映射的只屏蔽该维度；未映射的只记录，不影响其他槽位；见第 2.3 节 |

左手固定使用 `30:36`，右手固定使用 `36:42`，左右分别判断。
例如左手 6 维、右手 12 维时，保留左手，屏蔽右手。
通道数基于固定字段定义，不能因为某些通道在样例中恒定、重复或某帧缺失就减少计数。
因容量或字段定义而未映射手部，不影响 EEF、臂关节和独立夹爪字段各自的映射与有效性；
手部来源出现 NaN/Inf 时按第 2.3 节逐维屏蔽或仅记录，不影响 EEF 和夹爪。
填零只是占位，mask=0 不表示手指处于零角度。

### 5.2 固定关节表与 state/action 对齐

- 从元数据分别建立左右手的固定、有序关节表，记录名称、来源索引和通道数，保留源定义。
  对含明确关节编号的字段按数值编号排序，不按字符串字典序排序；其他命名采用显式映射配置。
- state/action 按同一张关节表进行名称匹配。仅排列不同就重排，不能仅凭数量相同认为语义一致，
  也不能在名称不匹配时只取交集来满足 6 维限制。
- 手指关节直接保留源数值，不设目标单位，不做度到弧度等单位换算，不做训练归一化。
- 保留机器人类型和关节名称。同一槽位只是统一了存储结构，
  不代表不同手型的第一个关节有相同物理作用，也不代表已经完成跨手型的动作重定向。

**本阶段不做数值异常判定或修复，留给后续质检。**
不根据最大值、中位数或其他数值范围推断是否漏做度到弧度转换；
不因为有限数值偏大而自动换算、裁剪、置零或屏蔽该手。
疑似单位错误、离群值和关节限位问题留给后续质检；原值保留不表示已验证其物理含义。
NaN/Inf 按第 2.3 节逐维屏蔽并记录，不引入有限数值的异常阈值。

### 5.3 保留原始手指数据

无论手部是否进入 55D，完整保留原始手指数据、字段定义以及未映射原因，
供后续质检或更大维度模板使用；不得用补零后的手部槽位覆盖原始列。

手部未进入 55D 时，原始同名手指仍参与第 4 节整集比较。手指存在差异就保留原动作，不触发移位。

## 6. 腰、头和底盘不接入

本次 RoboCOIN → 55D 转换不接入腰/躯干、头/颈和底盘，与当前 OpenWAM 的
RoboCOIN 读取路径保持一致。该决定适用于所有机器人和 episode，不依赖字段是否存在、
数值是否非零或是否随时间变化。

```python
state_unified[:, 42:51] = 0
action_unified[:, 42:51] = 0
mask_state[:, 42:51] = 0
mask_action[:, 42:51] = 0
```

这些零表示未接入的占位，不表示关节实际位于零位或底盘静止。
原始列及字段定义继续保留，不删除或覆盖；不从身体关节、腿关节或 IMU 推算底盘分量。
当前转换中这些槽位的值和 mask 始终为零。原始同名分量参与第 4 节整集比较，但不会因此被映射到这些槽位。

## 7. 双臂关节转换规则

双臂关节采用同事转换脚本的做法，state 从 `observation.state` 读取，action 从原始 `action` 读取。

### 7.1 按名称匹配和编号排序

- 分别完整匹配 `left_arm_joint_N_rad`、`right_arm_joint_N_rad`，提取整数编号 N 并升序排列。
- 每侧编号必须从 1 连续递增，不能缺号；字段名缺失、重复或歧义不能静默映射。
- state/action 分别根据各自元数据建立源索引，不假定两列的索引相同，
  不假定原始数组左臂在前，也不把数组前若干维直接当成左臂。
- 左臂写入 `0:7`，右臂写入 `7:14`。本地两个 Realman/RMC 样例原始右臂在 `0:7`、
  左臂在 `14:21`，按名称分别提取即可正确重排，不需要对角度取负。

### 7.2 容量和必需字段校验

| 每侧臂的关节定义 | 处理 |
|---|---|
| 连续的 1～7 | 7 维全部映射 |
| 连续的 1～6 | 写入该侧前 6 维，第 7 维填 0、mask=0 |
| 缺少一侧、关节数不是 6/7，或编号不连续 | 报错，该数据集映射不能继续生成 |
| 超过 7 个关节 | 不截取；因没有合格的臂映射而报错 |

上述要求对 state/action 的左右臂分别生效。与灵巧手超容量后屏蔽不同，
这里沿用同事将双臂视为必需字段的限制；本地已检查的 15 组元数据均为每侧连续 6 或 7 个臂关节。
臂关节映射本身不要求 state/action 数值相等；映射后再执行第 4 节整集判定。

### 7.3 数值、mask 和时间语义

按已确定的字段名提取源关节角，原值保留并存为 float32；`_rad` 仅用于名称匹配，
不据此新增单位校验或换算。有限值对应 mask=1，
任一分量出现 NaN/Inf 时按第 2.3 节仅屏蔽对应输出维度并记录错误；未映射分量只记录。
补出的第 7 维始终为无效占位。
不做 q01/q99 或其他训练归一化，不除以 π，不裁剪到 `[-π, π]`，不做角度环绕或 unwrap，
不根据数值大小自动推断或修正单位；可疑有限值留给后续质检。
不通过 EEF 反解关节角，不统一不同机器人关节轴的正方向或零位。
保留机器人类型、关节名称和原始列；同编号关节不代表跨机器人具有相同物理语义。

双臂先分别按同一原始行映射；是否将派生 action 改用下一帧 state，以及末帧处理，见第 4 节。
