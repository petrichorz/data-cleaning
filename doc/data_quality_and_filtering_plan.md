# 机器人数据筛选与质检方案

按照 Qwen-RobotManip 的管线组织，保留 S1–S5、C1–C3 原始编号。优先级 **0 高于 1**，各表按优先级排序：先实施 0，再实施 1。

## S 状态与动作信号检查

| 阶段 | 优先级 | 检查与处理 | 解决的问题 |
| --- | --- | --- | --- |
| S1 突变检测 | 0 | 结合平滑残差、加速度、jerk 检测异常，并计算 state/action 信号速度、加速度的 Z-score；检测阈值按机型设置 | 轨迹尖峰、突跳、异常瞬态及异常速度/加速度 |
| S2 状态与动作趋势对齐 | 0 | 比较同一 episode 内的数值动作指令 action 与实测状态 state，估计时延后检查状态反常先于 action、变化方向不符及跟随异常；补充幅度比和逐轴相关性检查，参考 OpenWAM，幅度比 ≥3 且逐轴相关系数 <0.5 时删除 episode | 时钟不同步、丢包、数值动作指令与实测状态不匹配 |
| S3 极值检测 | 0 | 按数据源、机型计算分位数范围，排除异常值 | 异常值污染归一化与训练 |
| S4 运动学一致性 | 1 | 用 URDF、关节角做正运动学，与记录的末端位姿比较，优先修正系统性错误 | 关节符号、TCP 偏移、旋转表示等错误 |
| S5 朝向对齐 | 1 | 校正基座、世界坐标和末端朝向约定 | 跨数据集坐标含义不一致 |

## C 跨模态与视频检查

| 阶段 | 优先级 | 检查与处理 | 解决的问题 |
| --- | --- | --- | --- |
| C3 视频质量 | 0 | 清理解码失败、冻结/重复帧、白帧/纯色帧、曝光异常及闪烁、黑帧、损坏、模糊和冗余静止段，保留夹爪闭合等关键帧 | 无效视觉监督，同时保护关键操作过程 |
| C1 指令一致性 | 1 | 切分子任务，由 VLM 判断，再对疑难样本做多模型复核 | 语言描述与实际演示不符 |
| C2 视频与状态一致性 | 1 | 比较机器人状态渲染投影与 SAM3 分割结果的重叠度，相机参数导致的问题先校正 | 图像与记录姿态不符、相机标定错误 |

依据：[Qwen-RobotManip 第 2.4 节](https://arxiv.org/html/2606.17846#S2.SS4)、[Figure 2 原图](https://arxiv.org/html/2606.17846v2/data_preprocess.png)。S1 的速度、加速度 Z-score 检测及按机型设置阈值的规则补充自 [LingBot-VLA 2.0 第 3.1.1 节](https://arxiv.org/html/2607.06403#S3.SS1.SSS1)。

S2 的幅度比与逐轴相关性规则补充自 [OpenWAM 第 5.2.2 节](https://arxiv.org/pdf/2609.07398#page=20)，数值为原文参考阈值。比较前需统一 action/state 的语义、单位和坐标；原文未展开幅度比计算和多轴判定方式，需在实现时明确。

## 现有工具的质检能力与覆盖判断

以下判断基于本地 Argus、EgoSmith、Forge 的代码实现，尚未用我们的数据运行验收。已有指标、已启用的异常规则和实际剔除能力分别判断，不将单个指标视为完整覆盖某一阶段。

- **Argus**：采集异常检查、VLM 指令与演示一致性判断、任务结果与执行质量标注，以及带时间证据的审阅。
- **EgoSmith**：第一视角视频筛选，检查重建手部姿态、相机轨迹、空间尺度和可见性。
- **Forge**：通用机器人数据检查、轨迹与视频质量指标、去重，以及按规则筛选和导出 episode。

### S 状态与动作信号检查的现有覆盖

| 阶段 | 已有能力 | 覆盖判断与待补齐 |
| --- | --- | --- |
| S1 突变检测 | **Argus**：按实际采样间隔计算速度、加速度、jerk 及中位数/MAD 稳健异常分数，检查尖峰、跳变后立即返回等异常；末端运动检查主要适用于手持夹爪数据。**EgoSmith**：手腕、手指和相机的相邻帧位移、旋转突变。**Forge**：jerk 平滑度、频谱平滑度、高频抖动和方向反转。 | **部分覆盖**。已有指标和局部异常规则；仍需统一机器人信号输入、按机型配置阈值，并明确异常定位和处置方式。MAD 稳健分数不能直接记作已经实现了按机型配置的普通 Z-score 规则。 |
| S2 状态与动作趋势对齐 | **Forge**：显式指定位置语义、action/state 对应维度和时延后，计算跟踪误差及疑似跟踪停滞。**Argus**：有针对 MolmoAct2 的主从臂时延估计，用于识别播放加速问题。 | **部分覆盖**。Forge 的时延由配置提供，Argus 的规则针对特定数据集；通用自动时延估计、幅度比与逐轴相关筛选尚未完整实现。必须使用真实数值控制指令与独立实测状态。 |
| S3 极值检测 | **EgoSmith**：用数据集 IQR 分布检查手腕、手指空间范围和 episode 平均相机运动，结合物理范围上限。**Forge**：在配置已知上下界后检查边界饱和。 | **部分覆盖**。EgoSmith 的统计筛选可借鉴，但对象是手部重建；仍需适配机器人 action/state，按数据源、机型分别统计分位数并制定处置规则。 |
| S4 运动学一致性 | 未找到“URDF + 关节角正运动学，与记录末端位姿比较”的质检实现；Argus 明确说明当前采集检查没有 FK。 | **需要补建**。包括关节约定、TCP 偏移和旋转表示错误的定位与校正。 |
| S5 朝向对齐 | EgoSmith 有世界坐标与相机坐标变换，以及旋转表示合法性检查。 | **尚未覆盖目标功能**。基础坐标运算不能替代跨数据集的基座、世界坐标和末端朝向约定检查与校正。 |

代码入口：[Argus 轨迹指标](../argus/checks/vendor/public_dataset_adapter_qc.py)、[Argus 采集检查与适用范围](../argus/checks/capture_qc.py)、[Argus MolmoAct2 时延检查](../argus/checks/timebase.py)、[Forge 跟踪诊断](../forge/forge/quality/diagnostics.py)、[EgoSmith 统计阈值](../egosmith/src/lib/pipeline/quality/thresholds.py)。

### C 跨模态与视频检查的现有覆盖

| 阶段 | 已有能力 | 覆盖判断与待补齐 |
| --- | --- | --- |
| C3 视频质量 | **Forge**：模糊、曝光异常、冻结、解码异常、分辨率变化、时间戳缺口，以及光流运动、疑似抖动和切镜。**Argus**：原始相机帧上的重复、冻结、极端曝光、解码和采集时钟检查。**EgoSmith**：手部出现、画面范围和相机运动稳定性筛选；可选 VLM 排除无操作、严重遮挡或模糊片段。 | **现有覆盖最多**。需统一阈值，区别正常静止与采集冻结；保护夹爪闭合等关键帧的冗余静止段裁剪尚未形成通用规则，原方案中的视频质量目标仍需逐项验收。 |
| C1 指令一致性 | **Argus**：把原始指令视为待验证的声明，根据视频独立描述实际任务，输出指令不符、任务结果、操作错误和证据时间。**EgoSmith**：VLM 判断有效手物交互和执行质量，生成多层语言标注。 | **部分覆盖，Argus 最接近目标**。EgoSmith 主要是内容筛选和生成标注；尚未找到疑难样本的多模型复核流程。 |
| C2 视频与状态一致性 | **Argus**：相机帧与 state 的配对检查、相机运动与记录运动的相关性、左右相机疑似串流，以及记录突跳而视频未突跳的检查。**EgoSmith**：将重建手部关键点投影到图像，检查越界和可见性。 | **部分覆盖**。尚未找到机器人状态渲染与 SAM3 分割的重叠比较。帧数或索引配对正确不能证明物理时间同步，仍需独立的时序一致性校验；手部投影越界检查也不能替代机器人几何重叠检查。 |

代码入口：[Forge 视频分析](../forge/forge/quality/video/analyzer.py)、[Argus 指令与数据问题判断](../argus/label/prompts.py)、[Argus 相机与运动配对](../argus/checks/stream_pairing.py)、[EgoSmith 手部投影](../egosmith/src/lib/pipeline/quality/projection.py)、[EgoSmith VLM 内容与质量判断](../egosmith/src/lib/annotation/prompts/without_clip/annotation_general_egocentric.txt)。

### 其他已有能力

- **数据完整性**：三个工具均有相应范围内的字段、维度或非有限值检查；Forge 还检查语言缺失、占位文本和相机元数据。具体检查范围取决于各自的数据适配器。
- **重复数据清理**：Forge 使用多相机关键帧感知哈希查找重复 episode，见[去重实现](../forge/forge/dedup/engine.py)。
- **筛选与报告**：Forge 可按质量分、异常标记和视频阈值筛选整个 episode，见[筛选入口](../forge/forge/filter/engine.py)；EgoSmith 输出筛选后的 manifest 和剔除原因，见[筛选入口](../egosmith/src/lib/pipeline/filtering/manifest_filter.py)；Argus 提供带时间证据的检查结果与审阅界面。
- **额外传感器检查**：Argus 检查传感器缺读、恒值、饱和、低更新率，以及深度无效、冻结和时间偏移，目前主要作为提示，见[传感器检查](../argus/checks/sensors.py)。

### 使用边界

1. **先确认 action 的真实含义**。Argus 的 `capture_qc` 使用 state 差分生成的 action，而非原始控制指令；EgoSmith 的 action 是下一帧重建手部姿态。二者都不能直接用于证明控制指令与实际执行是否匹配。Argus 针对 MolmoAct2 的主从臂时延检查是另一条专用路径。
2. **指标不等于剔除规则**。Argus 区分异常标记、提示和禁用规则，例如“超过 95% 静止”目前属于提示；传感器检查也主要是提示。未触发标记不能替代检查是否适用、是否成功执行的判断。
3. **部分能力需要显式开启**。Forge 视频分析需要启用相应配置；EgoSmith 启发式手部检测需要模型权重，默认配置的模型路径为空；VLM 流程需要相应模型或 API。EgoSmith 的标注有效性约束也取决于 `require_annotation` 等配置，不能按所有检查默认启用来计算覆盖率。
